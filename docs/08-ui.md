# 08 - UI design (Blazor Web App)

Status: **[D]** design + component code samples. The WebPortal project is Sprint 3-8 work (`docs/13-roadmap.md`); API contracts it consumes exist (`docs/api/openapi.yaml`) and the Device Service endpoints are implemented.

## 1. Application structure

```
src/WebPortal/AtmNexus.WebPortal/                 Blazor Web App (.NET 9), Interactive Server (NOC) + Interactive WebAssembly (Admin)
  Program.cs                                      OIDC cookie auth (BFF), HttpClient + token handler, SignalR client, localisation
  Components/
    Layout/        MainLayout.razor, NavMenu.razor, WallboardLayout.razor
    Shared/        HealthTile, HealthBadge, SeverityChip, CashUnitBar, DeviceTree, Timeline, DataGrid wrappers, ConfirmCommandDialog
    Pages/         Dashboard, AtmList, AtmDetail, Incidents, IncidentDetail, Alerts, Deployments, Admin/*
  Services/        ApiClient (typed, generated from openapi.yaml with NSwag), RealtimeClient (SignalR), AppState, Permissions
  State/           FleetState, FilterState, SelectedAtmState (scoped per circuit)
  wwwroot/         css tokens, icons
AtmNexus.WebPortal.Client/                        WASM components for Administration Portal (RenderMode.InteractiveWebAssembly)
```

* **Render modes**: `InteractiveServer` for NOC pages (sub-second push, tiny payloads, server-side tokens); `InteractiveWebAssembly` for the Administration Portal (forms/grids, offline-tolerant). Static SSR for login/error pages.
* **UI library**: Fluent UI Blazor (Microsoft) or MudBlazor; chart library: Apache ECharts via JS interop (heatmaps, sparklines). **Design tokens** in CSS variables, dark/light themes (NOC runs dark).
* **BFF pattern**: the portal holds access/refresh tokens server-side; browser gets only an HttpOnly cookie. `ApiClient` attaches the bearer via a `DelegatingHandler` (`IHttpContextAccessor` -> `GetTokenAsync`). The WASM client calls `/bff/api/*` on the portal, which proxies with the token.
* **Authorisation in UI**: `<AuthorizeView Policy="atm.command.execute">`; buttons are hidden **and** server-enforced (UI is not a control).
* **Accessibility/i18n**: WCAG 2.1 AA, keyboard-first (NOC operators), colour + icon + text for every status, `IStringLocalizer` resource files (EN first).

## 2. State management

| Concern | Mechanism |
|---|---|
| Fleet snapshot | `FleetState` (scoped per circuit): holds `DashboardDto` + `Dictionary<string, AtmSummary>` for visible rows; exposes `event Action Changed`; components call `StateHasChanged` via `InvokeAsync` |
| Real-time | `RealtimeClient` connects to `/hubs/status` (SignalR), **subscribes to groups only for what is on screen** (`region:SOUTH`, `branch:BR-0001`, `atm:ATM-000123`); messages are `AtmStatusChanged`, `AlertRaised`, `IncidentUpdated`; reconnect with jittered backoff; on reconnect does one full refresh to close the gap |
| Fallback | 30 s polling `GET /api/dashboard` if the hub is down (banner "live updates paused") |
| Filters | `FilterState` serialises to the **URL query string** (`NavigationManager`) so every view is linkable/bookmarkable and back/forward works |
| Server cache | `IMemoryCache` 5 s for dashboard aggregates (all circuits share) |
| Optimistic UI | commands show `PENDING` immediately; truth arrives via hub `CommandUpdated` |
| Forms | `EditForm` + DataAnnotations/FluentValidation, server-side validation errors mapped from `ValidationProblemDetails` |

Sample `FleetState` + live tile:

```csharp
public sealed class FleetState(ApiClient api, RealtimeClient rt) : IAsyncDisposable
{
    public DashboardDto? Dashboard { get; private set; }
    public event Action? Changed;

    public async Task InitAsync(string? region, CancellationToken ct)
    {
        Dashboard = await api.GetDashboardAsync(ct);
        await rt.SubscribeAsync($"region:{region ?? "ALL"}");
        rt.StatusChanged += async e =>
        {
            // cheap incremental update, then reconcile on a 15 s debounce to avoid drift
            Dashboard = Dashboard! with { ByHealthLevel = Apply(Dashboard.ByHealthLevel, e.PreviousLevel, e.CurrentLevel) };
            Changed?.Invoke();
        };
    }
    public ValueTask DisposeAsync() => rt.DisposeAsync();
}
```
```razor
@* Components/Shared/HealthTile.razor *@
```

### 3.7 Administration Portal
Sections: **Users** (search, roles, region scope, deactivate, effective permissions), **Roles & permissions** (matrix editor), **ATM master data** (CRUD, import with dry-run error grid, enrolment token), **Alert rules & maintenance windows**, **Notification routing / on-call**, **Integrations** (ITSM, SIEM, SMTP), **Audit viewer** (filters, chain-verification status, export), **Access review** (export who-has-what), **System** (agent version distribution, trusted-key coverage, certificate expiry histogram).

* **State**: per-page `EditContext`; unsaved-changes guard; every save shows the audit reference id returned by the API.

## 4. Performance and operability
* Server circuits per NOC user ~ 100 KB; 300 concurrent operators = 30 MB. Use **Azure SignalR Service** (or Redis backplane on-prem) so portal pods scale statelessly.
* Grids are server-paged and virtualised; maps cluster server-side above 5,000 markers (`GET /api/dashboard/map?bbox=&zoom=` returns clusters).
* Telemetry: browser errors -> OTel (`@opentelemetry/sdk-trace-web` via JS interop); Blazor circuit metrics (`aspnetcore.components.*`).
* Resilience: global `ErrorBoundary`, `Polly` retry/circuit on `ApiClient`, reconnect UI (`components-reconnect-modal`) customised for NOC.
